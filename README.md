# JSD13 - Week 09 React Assessment 🚀

ยินดีด้วยที่คุณเดินทางมาถึงสัปดาห์ที่ 9! Assessment นี้เป็นการทดสอบความเข้าใจพื้นฐานที่สำคัญที่สุดของการเขียน React ซึ่งประกอบไปด้วย **การทำ Routing**, **การจัดการ State/Effect**, **การยิง API ด้วย Axios** และ **การทำ Conditional Rendering (เงื่อนไขโชว์/ซ่อน คอมโพเนนต์)**

## 🧠 วิธีการคิดในการทำโจทย์ (Thought Process)

วิธีที่ง่ายและเป็นระบบที่สุดในการขึ้นโปรเจกต์ React คือการ **มองจากกรอบใหญ่ไปหากรอบเล็ก** (Top-down Approach):

### 1. โครงสร้างรวมและหน้าเว็บ (Routing & Layout)
- **โจทย์บอกให้มีเมนู Navigation ทะลุไปหน้า Home กับ Owner:**
  - สร้าง `<BrowserRouter>` (หรือ `createBrowserRouter` แบบที่เราใช้) ไว้ครอบแอป 
  - สร้างไฟล์ `<Layout />` เพื่อเก็บแถบเมนูด้านบน แล้วใช้ `<Outlet />` เป็นช่องว่างให้หน้าอื่น ๆ โผล่ขึ้นมา ทำให้ไม่ต้องเขียน `<NavBar />` ซ้ำในทุกหน้า
  - ท่านี้จะช่วยให้หน้าเว็บสามารถสลับ URL เปลี่ยนเป็น `Home` (`/`) หรือ `Owner` (`/owner`) ได้โดยที่หน้าไม่กะพริบ!

### 2. แบ่งส่วน UI ย่อย ๆ ออกเป็นชิ้น (Component Breakdown)
แทนที่จะเขียนโค้ดหลักร้อยบรรทัดกระจุกอยู่ใน `Home.jsx` เราจะตัดแบ่งชิ้นส่วน (Component) ให้เล็กและทำงานของใครของมัน:
- `<HomeTitle />` : รับหน้าที่โชว์ตัวหนังสือ "User Section" หรือ "Admin Section" เพียงอย่างเดียว (รับ props \`section\`)
- `<SectionButtons />` : เอาไว้รวมปุ่มกดสลับหน้าโหมด เมื่อกดแล้วค่อยโยนคำสั่ง \`setSection()\` กลับไปให้กล่องหลัก
- `<UserForm />` : เอาไว้วาดแบบฟอร์มเพิ่มข้อมูล 
- `<MemberTable />` : เอาไว้วาดตารางวนลูปข้อมูลสมาชิก

**ข้อดี:** ถ้าตารางพัง เราก็ไปแก้แค่ที่ตีตาราง ไม่สับสนกับฟอร์ม

### 3. การจัดการสถานะข้อมูล (State Management)
จุดนี้สำคัญที่สุด เราสร้าง **Hook แยก** ที่ชื่อว่า `useMembers.jsx`
- **ทำไมไม่เขียน State ใน Home.jsx ไปเลย?** 
  = เพราะหน้าที่ของ Home ควรจะคือการวาดหน้าตา UI อย่างเดียว! การทำงานหนักๆ (ยิง API, เพิ่ม, ลบ ข้อมูล) เราเลยแยกไปเขียนใน Custom Hook กองไว้ที่หนึ่งเพื่อความสะอาดตา
- ข้างใน `useMembers.jsx` เก็บข้อมูลอะไรบ้าง?
  1. `section`: จำไว้ว่าเราอยู่โหมด 'user', 'admin' หรือ 'normal'
  2. `members`: เก็บข้อมูลที่ดึงจาก API ล้วน ๆ
  3. `formData`: เก็บความเคลื่อนไหวจากคีย์บอร์ดที่ผู้ใช้พิมพ์ในแต่ละช่อง `<input>` (Controlled Component)

### 4. ซ่อน/โชว์ ของตามสถานการณ์ (Conditional Rendering)
เมื่อเอา State มารวมกับ UI (ข้อ 2 + ข้อ 3) 
- ถ้า `section === 'normal'` เราก็ไม่โชว์ตารางและไม่โชว์ฟอร์ม 
- ถ้า `section === 'user'` เราจะโชว์ `<MemberTable />` (แต่ส่งของไปบอกมันด้วยนะว่าไม่ต้องโชว์คอลัมน์ปุ่ม Delete)
- ถ้า `section === 'admin'` เราปล่อยของหมดเลย! โชว์ทั้งฟอร์ม `<UserForm />` และให้ตาราง `<MemberTable />` รับทราบว่าจงโชว์ปุ่ม ลบ ออกมา

### 5. เชื่อมต่อโลกภายนอก (API Integration)
เมื่อเราจัดการ Local State เสร็จ โค้ดจะเริ่มมีประโยชน์ก็ต่อเมื่อต่อฐานข้อมูล (MockAPI) สำเร็จ:
- ใช้ `useEffect()` สั่งว่า **"เปิดหน้าจอแอปขึ้นมาปุ๊บ ให้วิ่งไป `axios.get` ดึงข้อมูลมาใส่ตารางทันที"**
- สั่งที่ปุ่ม Save ว่า **"ถ้ากดเมื่อไหร่ ให้ `axios.post` ส่งข้อมูลใหม่ไปเซฟ"**
- และสั่งปุ่ม Delete ว่า **"ให้ `axios.delete(ไอดี)` แล้วโหลดใหม่ให้สะอาด"**

## 🛠 เทคโนโลยีที่ใช้งาน (Tech Stack)
- **Vite** : สร้างโปรเจกต์ React แบบติดจรวด
- **React Router (v6)** : จัดการทิศทางหน้าเว็บ เปลี่ยน URL อัตโนมัติ
- **Axios** : พระเอกที่รับจบการยิงข้อมูล HTTP Request ให้เป็นเรื่องง่าย
- **Tailwind CSS v4** : ไม่ต้องเขียน CSS ปกติ แต่วาดคลาสชื่อสไตล์ตรงๆ ลงใน Attribute ทันที ง่ายและลดเวลา
